# REMESH — магазин

Інтернет-магазин рибальських приманок і аксесуарів REMESH: Django 5.2 + HTMX. Каталог, кошик у сесії, замовлення з накладеним платежем, вибір відділення «Нової пошти», сповіщення менеджера в Telegram, адмінка українською.

## Локальний запуск

Команди — для Git Bash у корені проєкту. Перед усім виставте `PYTHONUTF8=1` (`export PYTHONUTF8=1`), інакше українські повідомлення команд у консолі Windows показуються кракозябрами.

```bash
py -3.14 -m venv .venv
.venv/Scripts/python -m pip install -r requirements-dev.txt
cp .env.example .env                       # за потреби відредагуйте значення
.venv/Scripts/python manage.py migrate
.venv/Scripts/python manage.py setup_roles   # група «Менеджер»
.venv/Scripts/python manage.py seed_remesh   # початковий каталог
.venv/Scripts/python manage.py createsuperuser
.venv/Scripts/python manage.py runserver
```

Магазин — <http://127.0.0.1:8000/>, адмінка — <http://127.0.0.1:8000/admin/>. Без `NOVA_POSHTA_API_KEY` пошук відділень не працює, без `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` сповіщення просто не надсилаються — замовлення при цьому оформлюються як зазвичай.

## Тести

```bash
.venv/Scripts/python -m pytest
```

Мережі тести не потребують: запити до «Нової пошти» й Telegram підмінені.

## Менеджер

Менеджер бачить в адмінці лише каталог і замовлення. Щоб додати його: в `/admin/` → «Користувачі» → «Додати», задайте логін і пароль, потім увімкніть «Статус персоналу» і додайте до групи «Менеджер» (група з'являється після `setup_roles`). Сам акаунт менеджера **не повинен** бути суперкористувачем: лише «Статус персоналу» і група «Менеджер», бо суперкористувач бачить в адмінці все й обмеження ролі на нього не діють.

## Деплой: Render + Neon

Це кроки, які робите ви зі своїми акаунтами.

**Перед першим деплоєм** заповніть ціни в `catalog/seed_data.py`: усі варіанти з `"price": None` команда `seed_remesh` пропускає. Починаючи з першого деплою `build.sh` запускає `seed_remesh --if-empty`: каталог створюється один раз, а видалене менеджером після цього не повертається. Тож варіанти, яких не було в першому наповненні, додавайте вже через адмінку. Виняток: якщо видалити всі товари, каталог стане порожнім, і наступний деплой знову наповнить його (`--if-empty`).

1. **GitHub.** Створіть порожній репозиторій і запуште код: `git remote add origin <url>` → `git push -u origin <гілка>`. Render збирає ту гілку, яку ви оберете (за замовчуванням `main`).
2. **Neon** (neon.tech). Створіть проєкт (база Postgres створюється разом із ним); на дашборді скопіюйте рядок підключення (`postgresql://…?sslmode=require`) — це `DATABASE_URL`.
3. **Telegram-бот** для сповіщень. У Telegram відкрийте @BotFather → `/newbot` → задайте назву й username; отримаєте токен — це `TELEGRAM_BOT_TOKEN`. Потім напишіть створеному боту будь-яке повідомлення (або додайте його в групу й напишіть у групі) і відкрийте у браузері `https://api.telegram.org/bot<ТОКЕН>/getUpdates`: у відповіді знайдіть `"chat":{"id":…}` — це `TELEGRAM_CHAT_ID` (для групи число від'ємне).
4. **Нова пошта.** У бізнес-кабінеті НП (розділ «Налаштування» → «Безпека») створіть ключ API — це `NOVA_POSHTA_API_KEY`.
5. **Render** (render.com). New → Blueprint → оберіть репозиторій; Render прочитає `render.yaml` і створить сервіс `remesh-shop`. Коли попросить значення змінних, що позначені `sync: false`, вкажіть `DATABASE_URL`, `NOVA_POSHTA_API_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`. `SITE_URL` поки можна залишити будь-яким.
6. Після першого деплою візьміть адресу сервісу (`https://remesh-shop-….onrender.com`), впишіть її в `SITE_URL` (Environment) і перезапустіть сервіс: за цією адресою в Telegram-повідомленні будуються посилання на замовлення в адмінці.
7. **Суперкористувач.** На безкоштовному Render немає консолі, тому створіть його локально проти бази Neon (міграції вже застосовані деплоєм):

   ```bash
   DATABASE_URL="<рядок з Neon>" .venv/Scripts/python manage.py createsuperuser
   ```

   Рядок містить пароль до бази — нікуди його не комітьте.

Перевірити налаштування безпеки перед деплоєм можна так:
`DEBUG=0 HTTPS=1 ALLOWED_HOSTS=example.com SECRET_KEY=<довгий-ключ> .venv/Scripts/python manage.py check --deploy` — помилок бути не повинно; допустимі лише попередження про HSTS (`security.W005`, `security.W021`): HSTS навмисно короткий і без `includeSubDomains`/preload.

### Обмеження безкоштовних планів

- Безкоштовний інстанс Render «засинає» після ~15 хвилин без запитів; перший візит після цього завантажується до хвилини.
- Диск безкоштовного Render тимчасовий. Демо-фото з репозиторію (`catalog/seed_images/`, перелічені в `catalog/seed_data.py`) `build.sh` відновлює при кожному деплої, навіть коли каталог уже наповнений; а фото, завантажені через адмінку, зникають після перезапуску чи нового деплою. Це лише для демо; для бойового магазину потрібні постійний диск або зовнішнє сховище для медіа. Дані в базі (Neon) при цьому зберігаються.
