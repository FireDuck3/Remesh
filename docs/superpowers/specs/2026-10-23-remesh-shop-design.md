## 3. Архітектура

- **Шлях проєкту:** `C:\dev\remesh-shop` (ASCII — кирилиця в шляху ламала інструменти).
- **Стек:** Python 3.12, Django 5.x, HTMX (один `<script>`), pytest + pytest-django.
- **БД:** SQLite локально; PostgreSQL у продакшні через `DATABASE_URL` (dj-database-url).
- **Конфіг:** змінні середовища (`SECRET_KEY`, `DEBUG`, `DATABASE_URL`, `ALLOWED_HOSTS`,
  `NOVA_POSHTA_API_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`); `.env.example` у репо,
  справжній `.env` — у `.gitignore`.

### Django-застосунки (кожен — одна відповідальність)

| App | Відповідає за | Залежить від |
|---|---|---|
| `catalog` | Category, Product, Variant, ProductImage; сторінки каталогу й товару | — |
| `cart` | Кошик у сесії (без реєстрації): додати / змінити к-сть / видалити / сума | `catalog` |
| `orders` | Форма оформлення, створення замовлення, статуси, сторінка «Дякуємо» | `cart`, `catalog`, `delivery`, `notify` |
| `delivery` | Клієнт API Нової Пошти: пошук міст і відділень/поштоматів | зовнішній HTTP |
| `notify` | Надсилання повідомлення про нове замовлення в Telegram | зовнішній HTTP |

`delivery` і `notify` — тонкі обгортки з чіткими функціями (`search_cities(query)`,
`list_warehouses(city_ref, query)`, `notify_new_order(order)`), щоб їх легко підміняти в тестах.

## 4. Модель даних

**Category**
- `name`, `slug` (unique), `position` (порядок у меню)

**Product**
- `category` (FK), `name`, `slug` (unique), `description` (текст), `is_active`, `created_at`

**ProductImage**
- `product` (FK), `image`, `position`

**Variant** — у КОЖНОГО товару є ≥ 1 варіант; ціна й залишок живуть тільки тут.
- `product` (FK), `name` (напр. «LOX UV»; для товару без варіантів — «Стандарт»),
  `sku` (unique), `price` (`Decimal`, 10,2, грн), `stock` (PositiveInteger), `is_active`

**Order**
- `number` (unique, формат `RM-0001`, генерується з id)
- `customer_name`, `phone` (нормалізований `+380XXXXXXXXX`)
- `np_city_ref`, `np_city_name`, `np_warehouse_ref`, `np_warehouse_name`
  (ref-поля порожні, якщо покупець ввів текстом — див. деградацію НП)
- `comment`, `payment_method` (поки лише `cod` — накладений платіж)
- `status`: `new` → `confirmed` → `shipped` → `completed`; або `cancelled`
- `ttn` (номер накладної, заповнює менеджер), `total` (`Decimal`), `created_at`

**OrderItem** — знімок на момент покупки (зміна ціни/назви не змінює старі замовлення).
- `order` (FK), `variant` (FK, `SET_NULL`), `product_name`, `variant_name`, `sku`,
  `unit_price`, `quantity`; `line_total` — обчислюване

## 5. Потік покупця

1. **Каталог** (`/`): сітка активних товарів, фільтр за категорією
   (напр. «Силіконові приманки», «Органайзери MEIHO»). Картка: фото, назва, ціна «від …».
2. **Товар** (`/p/<slug>/`): фото, опис, вибір варіанта (колір), ціна й наявність обраного
   варіанта, кількість, «В кошик». Додавання — HTMX POST; у відповідь оновлюється лічильник
   кошика в шапці (без перезавантаження).
3. **Кошик** (`/cart/`): позиції, зміна кількості й видалення через HTMX, сума.
   Кількість обмежена залишком варіанта.
4. **Оформлення** (`/checkout/`): ім'я, телефон, місто (HTMX-автокомпліт НП), відділення/поштомат
   обраного міста (HTMX-автокомпліт), коментар, оплата «накладений платіж».
5. **Створення замовлення** — одна транзакція (`transaction.atomic`):
   - `select_for_update` на варіанти з кошика;
   - перевірка: варіант активний і `stock >= quantity` для кожної позиції;
   - створення `Order` + `OrderItem` зі знімками; `stock -= quantity`;
   - очищення кошика; редирект на `/order/<number>/thanks/`.
6. **Після коміту** (`transaction.on_commit`): `notify_new_order(order)` → Telegram-чат магазину:
   номер, позиції, сума, ім'я, телефон, місто й відділення НП, коментар, посилання на замовлення
   в адмінці.

## 6. Адмінка (Django admin, українською)

- **Товари:** список з фото-мініатюрою, категорією, активністю; на сторінці товару — inline
  варіанти (ціна, залишок, активність) та inline фото. Ціна/залишок варіантів редагуються в
  списку варіантів (`list_editable`).
- **Замовлення:** список (номер, дата, клієнт, телефон, сума, статус), фільтр за статусом і датою,
  пошук за номером/телефоном/ім'ям; позиції — read-only inline; поля `status`, `ttn` редагуються;
  масові дії «Підтвердити», «Позначити відправленими».
- Скасування замовлення (`cancelled`) повертає залишки на склад (один раз — повторне скасування
  нічого не змінює).
- Окремий користувач-менеджер з правами лише на каталог і замовлення.

## 7. Обробка помилок і деградація

| Ситуація | Поведінка |
|---|---|
| Товар закінчився/вимкнений між кошиком і оформленням | Замовлення не створюється; форма повертається з переліком позицій, яких немає або менше; кошик коригується |
| Невалідний телефон / порожні поля | Помилки біля полів, введене зберігається |
| API НП недоступне або немає ключа | Автокомпліт вимикається; місто й відділення — звичайні текстові поля (ref-поля порожні) |
| Telegram недоступний / не налаштований | Замовлення створене; помилка — в лог; замовлення видно в адмінці. **Сповіщення ніколи не ламає продаж** |
| Порожній кошик на `/checkout/` | Редирект у кошик з повідомленням |
| Повторна відправка форми | Кошик уже порожній → редирект; дубль замовлення не створюється |

Відповіді API НП кешуються (Django cache, ~24 год для міст і відділень).

## 8. Вигляд

- Mobile-first: покупці приходять з Instagram, тобто з телефона.
- Стиль бренду REMESH: чорне й біле, логотип, мінімум акцентів; один CSS-файл без збирання.
- Шапка: логотип, категорії, лічильник кошика. Підвал: адреса, графік, телефон, Instagram.

## 9. Тестування (TDD, pytest-django)

- **cart:** додавання/злиття однакових варіантів, зміна кількості, обмеження залишком, сума.
- **orders:** успішне створення (знімки, зменшення залишку, номер `RM-xxxx`, очищення кошика);
  нестача залишку → без замовлення і без зміни залишків; вимкнений варіант; скасування повертає
  залишки рівно один раз; валідація телефону.
- **delivery:** парсинг відповідей НП на зафіксованих JSON-прикладах; поведінка без ключа/при
  помилці HTTP (підмінений HTTP).
- **notify:** формат повідомлення; помилка Telegram не кидає виняток назовні.
- **Наскрізний:** Django test client: каталог → товар → кошик → оформлення → «Дякуємо» →
  замовлення в БД → виклик сповіщення.
